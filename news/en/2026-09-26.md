## AI Models, Tooling, and Infrastructure
- **Multi-Model Routing Infrastructure**: OpenRouter has evolved into a neutral routing layer serving over 10 million developers, highlighting how competitive inference marketplaces and multi-model model strategies have become critical ecosystem infrastructure <sup>[1](<https://www.latent.space/p/openrouter>)</sup>.
- **OLMo 3 7B TPU Reproduction**: MaxText successfully reproduced AI2's OLMo 3 7B language model from scratch on Google Cloud TPUs using JAX/XLA, matching reference PyTorch-on-GPU evaluations while achieving up to 57.4% Model Flops Utilization (MFU) <sup>[2](<https://developers.googleblog.com/reproducing-olmo-3-7b-pre-training-in-maxtext-case-study-of-large-scale-training-on-tpus/>)</sup>.
- **Autonomous Post-Training**: Google introduced *autofinetune*, an autonomous framework using Tunix, Gemma, Cloud TPUs, and Gemini to run iterative Supervised Fine-Tuning and Reinforcement Learning (GRPO) loops—discovering optimal LoRA ranks and hyperparameters and committing verified improvements to Git <sup>[3](<https://developers.googleblog.com/autonomous-llm-post-training-with-tunix-on-tpus/>)</sup>.
- **Google AI & Colab Integration**: Google AI subscribers now receive premium Colab benefits, such as priority accelerator access, alongside uninterrupted background execution and Premium GPU access for Ultra subscribers <sup>[4](<https://developers.googleblog.com/colab-is-now-part-of-your-google-ai-plan/>)</sup>.

## Agents, RAG, and Evaluation
- **Kotlin Agent Development Kit (ADK) 1.0**: Google released ADK 1.0 for Kotlin, providing Kotlin Multiplatform (KMP) support, zero-reflection type-safe function calling via KSP, orchestration features like context compaction, and Android-first extensions for LiteRT-LM and AppSearch semantic memory <sup>[5](<https://developers.googleblog.com/announcing-adk-for-kotlin-10-building-production-ready-ai-agents-in-kotlin-android-and-beyond/>)</sup>.
- **Local Model Support in Antigravity**: The Google Antigravity SDK added support for offline, agentic workflows using models like Gemma 4 via LiteRT and drop-in compatibility with Ollama and vLLM for hybrid cloud-local architectures <sup>[6](<https://developers.googleblog.com/introducing-support-for-local-ai-models-in-the-antigravity-sdk/>)</sup>.
- **Harness Engineering for Coding Agents**: Engineering teams are adopting behavioral evaluations—fast, local, unit-style tests verifying discrete intermediate tool calls and file modifications—to complement macro benchmarks like SWE-bench and prevent regressions <sup>[7](<https://developers.googleblog.com/the-anatomy-of-harness-engineering-how-to-evaluate-iterate-and-guard-ai-coding-agents/>)</sup>.
- **REST APIs as MCP Tools**: Google Cloud API Gateway can now act as a native remote Model Context Protocol (MCP) server by annotating OpenAPI 3.x specifications, allowing standard REST operations to transcode incoming JSON-RPC requests automatically <sup>[8](<https://developers.googleblog.com/turn-your-rest-apis-into-mcp-tools-with-google-cloud-api-gateway/>)</sup>.

## Security, MLOps, and Developer Tooling
- **Zero-Trust Agent Governance**: The Gemini Enterprise Agent Platform introduced managed defenses including Model Armor for prompt screening, Semantic Governance Policies for evaluating tool intent against business logic, and Agent Anomaly Detection to catch runtime exploits <sup>[9](<https://developers.googleblog.com/build-zero-trust-ai-agents-that-judge-intent-not-just-syntax/>), [10](<https://developers.googleblog.com/agent-anomaly-detection-now-in-private-preview-on-the-gemini-enterprise-agent-platform/>)</sup>.
- **Open-Source Client SDK Generation**: Google partnered with Speakeasy to open-source its OpenAPI code generation suite under AGPLv3, enabling developers to integrate deterministic, multi-language SDK and CLI generators directly into CI pipelines <sup>[11](<https://developers.googleblog.com/why-client-sdk-generation-belongs-in-the-open/>)</sup>.
- **GitHub Copilot Enterprise Validation**: GitHub added an in-product validator for enterprise managed settings, automatically detecting malformed JSON and unsupported configurations in `copilot/managed-settings.json` and team mapping files <sup>[12](<https://github.blog/changelog/2026-09-25-enterprise-managed-settings-in-product-validator>)</sup>.
